# League Core: интегрированный спринт 30.10.2026

Код подготовлен в `feat/league-core-skill-sprint`. Действующие Supabase, Vercel,
Sites и Production v1.2.1 не изменялись. Никаких автоматических миграций при
сборке/запуске нет. `vercel.json` отключает Git deployments только этой ветки.

## Что изменено

- Заметки перемещаются из публичной `evenings.note` в `evening_notes` с RLS
  только для администратора. Все исходные заметки сохраняются транзакционно.
- Отложенные constraint triggers проверяют конечное состояние завершённых
  партий после INSERT, UPDATE и изменения/удаления мест. Обязательны правильные
  9/10 мест, роли и отдельный ведущий. Технический результат/удаление требуют причины.
- Изменения игроков, вечеров, записей и партий доступны через ограниченные
  транзакционные RPC с проверкой `expected_revision`. Прямые записи API
  отозваны, в том числе для администраторов; триггеры регистрации и прежняя
  привязка аккаунтов продолжают работать как серверные операции.
- Версии из одной последовательности не повторяются после удаления/создания
  RSVP. Все значимые изменения сохраняются в закрытом `club_audit`.
- RSVP закрывается при начале/завершении/отмене вечера для всех ролей.
  `going` и `late` вместе ограничены вместимостью; `maybe` не резервирует место.
  При заполнении мест пользователь может выбрать «Возможно». Автоматического
  листа ожидания и продвижения очереди в этом спринте нет.
- Создание/удаление партий и редактирование/удаление вечеров блокируют вечер
  внутри транзакции. Нумерация партий выделяется сервером. CAS не позволяет
  старому редактору молча заменить новый результат; одинаковый старый запрос
  отклоняется, а не повторно применяется. Клиент не подменяет версию грязной
  формы при обновлении серверных props. При deadlock PostgreSQL откатывает
  действие; интерфейс предлагает повторить его.
- `league_snapshot()` отдаёт один публичный MVCC-снимок JSON без приватных
  заметок, account IDs и незавершённых ролей. Он не ограничен стандартным числом
  строк REST. Это полный клубный снимок, не потоковая аналитическая платформа:
  размер JSON и стоимость полной ковариации нужно контролировать при росте клуба.
- Один источник/политика используются для истории, протоколов, профилей,
  статистики и рейтинга: завершённые, не аннулированные партии неотменённых
  вечеров, включая ещё открытые вечера. Отсутствие влияния на Skill не скрывает
  партию из описательной статистики. Закрытые пустые вечера остаются в истории;
  счётчик вечеров на главной использует ту же историю.
- `played_at` берётся из даты вечера, а не времени ввода; `finished_at` остаётся
  техническим временем завершения записи. Дата вечера с партиями защищена от
  случайной смены через UI. Сезон можно явно назначить/исправить, с журналом и
  пересчётом рейтинга. Рейтинг сортирует партии по оригинальным правилам v33:
  дата вечера в Вене, ID вечера, номер партии, ID партии.

## Оригинальная team-logit-v1

`src/lib/league/legacy/model.ts` и `referee-protocol.ts` скопированы **без изменения
байтов** из исходного коммита Sites v33
`a4e6cbc1bc486e97915043779f3ba89a051cfa10`. SHA-256 перечислены в `provenance.json`.
SHA модели: `1adac23c3fabb53a2f293eeaf316ab8379c64e2f6cdf85e14ce6e3a809ce39da`.
ESLint не переписывает эти файлы; TypeScript продолжает их проверять.

Адаптер `league/core.ts` переводит новый storage в исходные структуры.
Параметры, полный ковариационный расчёт и правила предварительного статуса
не менялись. Экспериментальных турнирных оценок нет.

Основной Skill исключает Short9, ничьи, технические результаты, удаления,
некорректные/несовместимые и аннулированные партии. Обычные фолы сами по себе
не дают штрафа. Вечера без назначенного сезона остаются в истории, но не
участвуют в Skill: им не придумывается сезонный baseline. Админская форма
теперь позволяет выбирать сезон. Исторический `draw` преобразуется во входной
`cancelled` оригинального алгоритма только в адаптере, без изменения БД/движка.

Профиль, таблица и график получают одну оценку. На графике интервал 95% и
переходы к партиям; точки включают обновления после чужих игр из-за общей
ковариации. Число всех партий и число подходящих Classic10 показаны отдельно.
Предварительным оценкам не присваивается официальное место.

Эталоны: исходный baseline v33, golden JSON, рассчитанный исходным модулем
**до интеграции**, замороженная ранняя формула. Golden сравнивается целиком,
включая интервалы и историю. На 80 синтетических префиксах оценки и прогнозы
сравниваются с замороженной формулой; различие политики истории отсутствующих
игроков известно и проверено отдельно. Исходный baseline также содержит
удалённые вечера: адаптер не возвращает их в рейтинг.

## Движок ведущего

`referee/engine.ts` предоставляет настоящий исходный движок v33, а не имитацию
экрана. Сохранены проверка переходов, версии Short9, фолы/голосования,
компенсирующие undo/redo, checksum и импорт/экспорт.

`referee/bridge.ts` готовит результат для существующего `save_game` CAS API:
нужен незавершённый целевой game, явное сопоставление всех мест UUID-игрокам,
отдельный ведущий, известные роли и наблюдавшийся результат. По имени аккаунты
не сопоставляются. Функция не делает сетевых запросов и ничего не сохраняет.
Оригинальный приватный протокол не попадает в публичный кэш.

Ещё НЕ реализованы экран `/referee`, права назначенного ведущего, хранилище
протоколов, облачная синхронизация, восстановление таймера и принятие результата
организатором. Для них теперь есть проверенный движок и контракт перехода к
новой архитектуре. Перед подключением импорта нужно хранить приватный протокол
и provenance вместе с результатом и предотвращать повторный импорт draftId;
нынешний bridge не является готовым пользовательским импортом.

## Проверки

Локальный результат спринта: 44 теста PASS (включая 21 группу исходного
контракта ведущего и 80 сравнений префиксов модели), ESLint PASS, TypeScript
PASS, чистая установка `npm ci` в отдельной папке PASS. Стандартная сборка
упирается в `binding to a port: Operation not permitted` CSS-worker Turbopack.

Node 24 рекомендуется, минимальная версия 22.13.0:

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Тесты используют временный in-memory PostgreSQL/PGlite, синтетические auth users
и стандартные табличные API grants. Проверяются чистая установка и обновление
прежней схемы с данными, права/приватность, отложенные ограничения, сохранение
аккаунтов, RSVP, CAS, общий публичный снимок, эталоны модели и движок ведущего.
Это не проверка действующей Supabase или конкурирующих физических PG-сессий.
Гонки проверены воспроизводимым чередованием запросов двух редакторов;
дополнительно используются реальные PostgreSQL row locks и unique constraints.

В локальном управляемом окружении сборка может блокироваться запретом
Turbopack worker на binding локального порта. Это ограничение среды, а не
успешная production-сборка. CI также запускает стандартный `npm run build`.
Физический iPad/Safari и полноценные пользовательские формы под входом требуют
отдельной проверки в тестовом приложении после применения миграции в тестовой БД.

## Применение позднее, без изменения действующей базы сейчас

Четвёртая миграция `20261030030000_league_core.sql` — один транзакционный набор.
Сначала проверить резервную копию и применить все миграции в отдельном Supabase
проекте, затем проверить соответствующий код с **этой** тестовой базой.
Старый код несовместим с отозванными прямыми записями и удалённым `evenings.note`;
новый код требует четвёртой миграции. Нельзя выкладывать половину изменения.

Миграция не исправляет старые результаты и не выкидывает лишние RSVP сама:
при исторически некорректной завершённой партии или переполнении она откатится
целиком. Сначала нужно разобрать конкретные записи в копии, сохранив источник.
`seed.sql` предназначен только для пустой тестовой базы и выполняется после
всех четырёх миграций. Существующие боевые профили/партии не заменяются seed.

Откат после будущего применения требует согласованного отката кода и схемы;
откат только приложения не восстановит прежние разрешения API. Удалять новые
данные или восстанавливать старую базу для отката этого спринта не предлагается.
