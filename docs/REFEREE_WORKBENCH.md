# Пульт ведущего

Путь `/admin/referee`. Доступ предоставляется действующему администратору
клуба. Пульт использует исходный движок v33 для Classic10 и Short9. Редакция
регламента хранится вместе с протоколом и при импорте сохраняется.

## Проведение партии

1. Создайте протокол и выберите ведущего из реестра игроков либо введите
   его никнейм. На круглом столе нажмите на место и назначьте игрока и роль.
   Выбор из реестра запоминает UUID. Для игры вне реестра доступен ручной ввод.
2. Начните N0. Пульт открывает отстрел и проверки в соответствии с редакцией
   формата. В дневной фазе доступны речи, выставления, подсчёт голосов,
   защиты и переголосование. Фолы, голосования, удаления и исправления
   остаются в журнале. Отмена и повтор добавляют записи в журнал.
3. Укажите наблюдавшийся результат и основание. При необходимости уточните
   роль или никнейм с указанием причины. Итоги с неопределённым исходом и
   отменённые протоколы остаются в архиве.
4. Сохраните копию через «Сохранить в облако» или экспортируйте JSON.
   В локальный архив протокол попадает автоматически. Импорт проверяет
   версию, последовательность и SHA-256. Для восстановления на другом
   устройстве используется облако либо проверенный JSON.

Речь запускает таймер с учётом фолов. Для защиты предусмотрены 30 секунд,
для ночной проверки 20 секунд, для последнего слова 60 секунд. Таймер
ставится на паузу при скрытии вкладки. Сам таймер работает в открытой
вкладке. Для скрытия экрана используйте кнопку или Esc.

## Утверждение для истории

1. В админке вечера создайте черновик партии нужного формата.
2. Откройте завершённый протокол и сохраните его в облаке.
3. Нажмите «Проверить состав и утвердить». Выберите этот черновик
   партии, сверьте места, роли, ведущего и пробелы в наблюдениях.
   Уже записанные UUID фиксированы. Старые протоколы с ручными никами
   требуют явного сопоставления с реестром.
4. Подтвердите публикацию. Ссылка откроет карточку игры с рассадкой, фолами,
   ролями и официальным исходом. Подробный журнал остаётся закрытым.

## Хранение и конфликты

- Сервер проверяет права, SHA-256 и воспроизводит протокол перед
  утверждением. Postgres проверяет владельца, ревизии и соответствие
  результата закрытым наблюдениям. Запись результата и квитанция
  утверждения сохраняются одной транзакцией.
- Допускается одна квитанция на ID протокола и одна на ID партии.
  Точный повтор запроса возвращает ту же квитанцию. Исправление или
  удаление партии администратором в League Core сохраняет квитанцию.
- При расхождении устройств пульт сохраняет местные правки для экспорта.
  Синхронизация выполняется кнопкой. Чтобы принять другую версию,
  восстановите её из облака после сохранения своих правок.
- Локальные записи разделены по учётным записям. Для восстановления
  неразделённого архива предыдущей версии есть отдельный пункт в пульте.
  Используйте доверенное устройство и храните экспорт закрытого протокола
  там, где доступ контролирует ведущий.
