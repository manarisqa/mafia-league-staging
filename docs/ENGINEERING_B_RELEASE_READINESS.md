## Перезапуск партии

«Начать игру заново» доступно через «Ещё», включая экран протокола, и прямо
из открытого закрытого ночного действия. Подтверждение оставляет тот же вечер,
номер партии, формат, ведущего, порядок мест и организационные решения.
Новая попытка получает отдельные UUID и код восстановления. Пульт открывает
запись карт, очищает игровые события и использует новые ключи таймера. При
выходе к списку черновиков текущую попытку можно открыть снова.

- Для того же браузера смена попытки и снятие прежнего результата с очереди
  происходят одной записью. Вкладки используют ревизии и Web Locks. Старая
  вкладка переходит к новой попытке. Импорт отменённого JSON в этот браузер
  блокируется. На другом устройстве импортированная копия участвует в
  FairQueue только после серверной сверки.
- При восстановлении сети пульт отправляет только квитанции отмен. Результат
  новой попытки ведущий отправляет вручную после сверки квитанций. Сервер
  сохраняет закрытую связь UUID отменённой и новой попыток и время отмены.
  У сохранённой отменённой попытки сервер очищает журнал действий. Старый
  UUID остаётся заблокированным для чтения, сохранения и отправки, даже если
  первоначальный протокол существовал только на устройстве.
- Если отправка уже была принята, например при потере ответа, сервер
  сохраняет исходный протокол. Пульт позволяет открыть его и продолжить
  предусмотренную административную процедуру. Если другое устройство уже
  отменило этот UUID, продолжать следует на том устройстве с новой попыткой.
  Независимое устройство узнаёт об офлайн-отмене при сверке с сервером.
- Сервер принимает один ожидающий протокол на номер партии за вечер.
  Существующая атомарная публикация и повтор запроса с тем же результатом
  сохраняют одну официальную игру. Локальная история подачи для FairQueue
  берёт одну сыгранную партию на пару «вечер + номер», исключая отмену,
  отзыв, отклонение и архивирование. FairSeat использует опубликованные
  партии из каталога.

## Резервная копия, восстановление и перенос

[Скрипт архива и восстановления](../scripts/club-backup.sh) использует
`pg_dump` custom format для всей базы одним снимком, включает схемы,
связи, данные Auth, закрытые протоколы, владельцев и grants. В bundle
хранятся архив, список объектов и SHA-256. Команда `verify` проверяет
SHA-256 и полный проход декомпрессии. Архив и SQL-выгрузки остаются в
закрытом хранилище. Для работы подключаются через libpq с `PGSERVICE` и
закрытым `PGPASSFILE`. Клиентские утилиты должны поддерживать версию
исходного сервера.

1. Зафиксировать согласованную версию схемы и приложения и при отдельном
   разрешении владельца остановить запись на время финального снимка.
   Сверить имена проектов и БД. Сформировать архив и два отпечатка.

   ```sh
   umask 077
   export PGSERVICE=club_source
   bash scripts/club-backup.sh backup /private/club-snapshot
   bash scripts/club-backup.sh verify /private/club-snapshot
   psql -XqAt -v ON_ERROR_STOP=1 -f scripts/club-fingerprint.sql > /private/source.rows
   psql -XqAt -v ON_ERROR_STOP=1 -c 'select public.league_snapshot()' |
     node --import tsx scripts/club-skill.ts > /private/source.skill
   ```

2. Подготовить изолированный PostgreSQL с заранее настроенными ролями и
   требуемыми расширениями. Создать пустую БД из `template0` и применить
   архив в одной транзакции. Скрипт отклоняет повторный импорт и
   восстановление в инициализированную БД.

   ```sh
   export PGSERVICE=club_isolated
   bash scripts/club-backup.sh restore-empty /private/club-snapshot club_restore
   psql -d club_restore -XqAt -v ON_ERROR_STOP=1 -f scripts/club-fingerprint.sql > /private/restore.rows
   psql -d club_restore -XqAt -v ON_ERROR_STOP=1 -c 'select public.league_snapshot()' |
     node --import tsx scripts/club-skill.ts > /private/restore.skill
   diff -u /private/source.rows /private/restore.rows
   diff -u /private/source.skill /private/restore.skill
   ```

3. Сверить schema-only dump, миграции и Auth/RLS до переключения. Если
   целевой проект управляется Supabase, для полного переноса использовать
   поддерживаемый этим проектом managed restore/clone и повторить проверки
   на восстановленной копии. Утилита `restore-empty` рассчитана на пустой
   PostgreSQL. Предварительно созданные схемы managed Supabase, роли кластера,
   OAuth/SMTP, API-ключи и внешние хранилища настраиваются средствами платформы.
4. Только после совпадения отпечатков проверить доступы гостя, игрока и
   админа, открытие архивной игры и маршрут пробного протокола. При
   несовпадении оставить прежнюю привязку. После разрешённого cutover
   исходную БД и предыдущий deployment сохранить для отката. Если в новой
   БД уже была запись, перед возвратом остановить запись и сверить дельту
   транзакций по ID. Слепой возврат может потерять новые результаты.

### Воспроизведение на синтетических данных

После `npm ci` с Node 24 и Docker, в отдельных терминалах запустить локальную
БД, шлюз и Next.js. Файл параметров ниже содержит только локальные
синтетические значения.

```sh
bash tests/browser/local-stack.sh start > /tmp/mafia-readiness.env
node tests/browser/local-gateway.mjs
```

```sh
set -a
source /tmp/mafia-readiness.env
set +a
npm run build
npm start -- --hostname 127.0.0.1 --port 55420
```

```sh
QA_RESTART_ONLY=1 npm run test:browser
npm run test:browser
QA_EDGE_ONLY=1 npm run test:browser
bash tests/browser/backup-roundtrip.sh
bash tests/browser/local-stack.sh stop
```

Для проверки обновления начать с прежней схемы в отдельном
синтетическом инстансе.

```sh
QA_STACK_NAME=mafia-upgrade QA_BEFORE_RESTART_MIGRATION=1 \
  bash tests/browser/local-stack.sh start > /tmp/mafia-upgrade.env
QA_STACK_NAME=mafia-upgrade bash tests/browser/backup-roundtrip.sh upgrade
QA_STACK_NAME=mafia-upgrade bash tests/browser/local-stack.sh stop
```

## Действия владельца перед клубным использованием

1. В защищённых настройках сверить Vercel URL и publishable key обеих
   сборок с тестовым проектом, отдельно сверить идентичность рабочей БД.
   Передать только подтверждение привязок и установленных версий схемы.
2. Отдельно разрешить применение отсутствующих добавочных миграций в
   проверенном **тестовом** проекте. После этого выполнить один короткий
   E2E на Safari/iPad с синтетической партией в защищённой Preview,
   включая перезапуск, отправку и утверждение.
3. Если нужен фактический перенос клубных данных, отдельно разрешить
   доступ к источнику, клонирование в согласованную цель и окно записи.
   Описанная процедура позволяет автоматизировать технические проверки
   после получения этого доступа.
