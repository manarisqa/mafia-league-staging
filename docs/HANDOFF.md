# Mafia League — передача проекта в новую сессию

Дата: 30 октября 2026. Последний коммит в `main`: `bc27492` (pull request #8).
Этот файл описывает, что сделано, как всё устроено, какие правила работы приняты и что делать дальше.

## 1. Что за проект

Сайт клуба спортивной Мафии в Граце (Австрия). Делают двое непрофессиональных программистов
(владелец проекта и его друг) вместе с Claude. Раньше друг делал сайт с ChatGPT, но решили
**начать с нуля**. Архив от ChatGPT (`CLAUDE_MAFIA_LEAGUE_KNOWLEDGE_HANDOFF_2026-10-30.zip` в «Загрузках»)
используем **только как ориентир по виду экранов** (картинки `support/design_references/`) и по
правилам игры. Процессные инструкции из архива (гейты, Staging №33, Work, Production) игнорируем.

### Принятые решения
- Стиль: **чёрно-красный** (Black & Crimson). Цвета в `src/app/globals.css`, названы по роли.
- Язык: **только русский**. Другие языки позже.
- Домена пока нет (сайт на `*.vercel.app`).
- Рейтинг: **простая формула** `1000 + 25 × (победы − поражения)`, ничья не меняет рейтинг.
  Сложная модель League Skill (`team-logit-v1`) из архива в проект не переносилась: в архиве нет её кода,
  только описание и результаты тестов. Вернуться к ней можно, когда накопится 200–300 игр.
- Игроки входят по **почте и паролю без писем**. Новые игроки записываются на вечер сразу,
  админ разбирает лишние аккаунты потом.
- Расписание: один физический стол, форматы «Классика 10» (10 игроков + ведущий) и Short9 (9 игроков + ведущий).
  Ведущий — отдельный человек, не играет за столом в этой же партии.
- Красные = мирные и шериф. Чёрные = дон и мафия. В «Классике 10»: 6 мирных, шериф, дон, 2 мафии.
  В Short9: 5 мирных, шериф, дон, 2 мафии. Short9 в архиве не влияет на «большой» рейтинг,
  у нас сейчас считается наравне (простая формула), это стоит обсудить.

## 2. Технологии

- **Next.js 16.4** (App Router), TypeScript, Tailwind 4. В `next.config.ts` включены **Cache Components**:
  нельзя просто вызывать `new Date()` или читать данные без `Suspense` / `"use cache"`.
  У этой версии Next есть свои отличия от привычной — смотрите документацию в `node_modules/next/dist/docs/`.
  Файл `proxy.ts` (раньше `middleware.ts`) лежит в `src/proxy.ts`.
- **Supabase** (Postgres + Auth). Ключи в `.env.local` (в Git не попадает), образец в `.env.example`.
- **Vercel** — хостинг. Сайт: https://mafia-league-staging.vercel.app/
- Node 26, npm 11.

### Порядок работы с кодом
1. Новая ветка от свежего `main`.
2. Коммиты, `git push -u origin <ветка>`, pull request в `manarisqa/mafia-league-staging`.
3. **Влить pull request только после явного «да» владельца**: система блокирует слияние без подтверждения.
4. После слияния: `git checkout main && git pull origin main && git push fork main` — иначе Vercel не обновится.
5. Vercel пересоберёт сайт за 1–2 минуты. Проверить: Vercel → Deployments, статус Ready.

### Структура кода (`src/`)
- `app/` — страницы. Публичные: `/`, `/evenings`, `/players`, `/rating`, `/learn`, `/history` (заглушка),
  `/login`, `/register`. Админка: `/admin`, `/admin/players`, `/admin/evenings`, `/admin/evenings/[id]`,
  `/admin/games`, `/admin/games/[id]`.
- `components/` — шапка, подвал, кнопки входа, общие блоки, схема стола.
- `lib/data.ts` — **публичные** данные с кэшем (`"use cache"`, тег `club`). Только публичный клиент!
- `lib/admin-data.ts` — данные админки **без кэша**, от имени вошедшего админа.
  Никогда не передавать клиент админа в функции с `"use cache"`: данные попадут в общий кэш.
- `lib/auth.ts` — `requireAdmin()`: вызывать в начале **каждой** админской страницы и **каждого**
  серверного действия (действия — открытые адреса).
- `lib/keep-form.ts` — `keepFormSubmit()`: отправка формы без сброса полей (см. «Уроки»).
- `lib/rating.ts`, `lib/format.ts` (даты по Вене, подписи), `lib/game-composition.ts` (подсчёт ролей).
- `proxy.ts` — обновляет сессию входа на всех страницах и отправляет гостей с `/admin` на `/login`.

### База данных (`supabase/`)
Три файла в `supabase/migrations/`, выполняются **по порядку** в Supabase → SQL Editor. Все три уже выполнены
на рабочей базе владельца:
1. `20261030000000_init.sql` — таблицы (`players`, `admins`, `seasons`, `evenings`, `evening_signups`,
   `games`, `game_players`), правила доступа (RLS), проверки состава партии.
2. `20261030010000_player_accounts.sql` — профиль игрока создаётся при регистрации;
   `link_account()` привязывает аккаунт к старому профилю (только админ).
3. `20261030020000_save_game.sql` — `save_game()` сохраняет рассадку, роли и результат одной операцией.

`supabase/seed.sql` — **демо-данные** (12 игроков «Игрок 01…12», вечер, две партии). Загружены на рабочую базу.
`supabase/README.md` — подробная инструкция по настройке.

Ключевые правила базы:
- Читать игроков, вечера, сезоны и завершённые партии может любой.
- Роли в идущей партии видны только админу. Записи на вечер видны админу и самому игроку;
  публично виден только список «придёт/опоздает» (view `evening_participants`).
- Писать клубные данные может только админ. Игрок меняет только свою запись на вечер.
- Завершить партию можно только с верным составом, победителем и ведущим вне стола.

### Настройки в Supabase (сделаны)
- Authentication → Email: регистрация включена, **Confirm email выключено**.
- Администратор: пользователь создан в Authentication → Users и добавлен в таблицу `admins` SQL-запросом

### Переменные окружения (и в `.env.local`, и в настройках проекта Vercel)
`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SHOW_DEMO_BADGE=true`.
Ключ публичный, но **secret / service_role ключ нигде не использовать и не присылать**.
`NEXT_PUBLIC_SHOW_DEMO_BADGE=true` показывает пометку «Демонстрационные данные»; удалить, когда внесут настоящих игроков.

## 6. Уроки и ловушки (важно знать новой сессии)

- **Формы React 19 сбрасывают поля** после `<form action>`: из-за этого был «баг с ролями»
  (после сохранения поля становились пустыми, и дальше отправлялось неверное). Для всех форм с полями
  использовать `onSubmit={keepFormSubmit(action)}`, а не `action={action}`.
- **Vercel Security Checkpoint**: из этой сети `curl` и CLI Vercel получают страницу проверки на бота (403).
  Обходить нельзя. `vercel login` из этой сети не работает вообще. Проверять сайт через браузер владельца.
  Скриншоты встроенного браузера в некоторые моменты не снимались, помогала проверка через DOM.
- **Проект не хранить в «Документах»**: iCloud создаёт копии файлов с « 2», « 3» в имени, это ломает сборку
  («Failed to open database»). Поэтому проект перенесён в `~/Projects`.
- **Порт 3100 мог занять старый сервер**: перед проверкой убивать процесс по порту
  (`lsof -ti tcp:3100 | xargs -r kill`), иначе тестируется старая сборка.
- **Кэш**: после изменений в админке вызывается `updateTag("club")`; во всех публичных
  функциях с `"use cache"` стоит `cacheTag("club")`.
- **Конфликт «админ vs публичный кэш»**: не использовать `lib/data.ts` в админке и наоборот.
- **Предупреждение Supabase «destructive operations»** при запуске SQL — это из-за слов `delete`/`revoke`
  внутри функций. Данные оно не трогает.
- Реальные пароли и ключи **не вводить и не присылать в чат**. Вход и формы под админом проверяет владелец.
